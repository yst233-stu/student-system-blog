本系统最初采用 PySide6 桌面版，后逐步将各模块迁移至 Flask + HTML 网页版。本文记录的是将「体能成绩录入」模块从桌面版迁移到网页版过程中，遇到的 8 个真实问题及解决方案。

整个迁移过程由 AI 辅助生成代码，本人负责需求定义、方案选择和问题审查。

二、迁移方案概览

改造范围：仅体能成绩录入模块，不涉及学生信息和学习成绩模块。

后端：在已有 app.py 中新增体能成绩相关 API。

前端：在 index.html 中新增"体能成绩"Tab 页。

数据层：操作达梦数据库中已有的 PHYSICAL_SCORE 表，结构不变。

三、踩坑记录（8 个问题 + 解决方案）

❌ 问题 1：Flask 路由冲突 — "View function mapping is overwriting an existing endpoint"

报错 
AssertionError: View function mapping is overwriting an existing endpoint function: physical

原因：桌面版迁移时已经注册过一个 /api/physical 的路由，AI 新增代码时没检查已有路由，导致重复定义。

解决方案

搜索整个 app.py，删除重复的路由定义，只保留一个：

@app.route('/api/physical', methods=['GET'])
def get_physical_scores():
    rows = execute_query("SELECT * FROM PHYSICAL_SCORE ORDER BY STUDENT_ID")
    return jsonify(rows)

@app.route('/api/physical', methods=['POST'])
def add_physical_score():
    data = request.json
    sql = "INSERT INTO PHYSICAL_SCORE (STUDENT_ID, ITEM, SCORE, TEST_DATE) VALUES (?,?,?,?)"
    execute_non_query(sql, (data['sid'], data['item'], data['score'], data['date']))
    return jsonify({'success': True})
经验

AI 生成代码时，不会自动检查已有路由。每次新增接口前，先全局搜索路由路径是否已存在。

❌ 问题 2：前端表单校验失效 — 空值直接插进数据库

现象

不填成绩直接点"新增"，没有提示，空值直接插进了数据库。

原因

AI 生成了 validatePhysical() 函数，但 addPhysical() 里没有调用它。桌面版 Qt 的 QMessageBox.warning() 是自动弹出的，网页版需要手动在 JS 里调用校验函数。

解决方案

在 addPhysical() 开头加上校验调用：

function addPhysical() {
    if (!validatePhysical()) return;  // ✅ 加上这一行

    const data = {
        sid: document.getElementById('physical-sid').value,
        item: document.getElementById('physical-item').value,
        score: document.getElementById('physical-score').value,
        date: document.getElementById('physical-date').value
    };

    fetch('/api/physical', {
        method: 'POST',
        headers: {'Content-Type': 'application/json'},
        body: JSON.stringify(data)
    }).then(res => res.json())
      .then(json => {
          if (json.success) loadPhysicalTable();
          else alert('新增失败');
      });
}

validatePhysical() 函数示例：

function validatePhysical() {
    const sid = document.getElementById('physical-sid').value.trim();
    const score = document.getElementById('physical-score').value.trim();

    if (!sid) { alert('请输入学号'); return false; }
    if (!score) { alert('请输入成绩'); return false; }
    if (isNaN(Number(score))) { alert('成绩必须是数字'); return false; }
    return true;
}
经验

AI 会把函数都写出来，但函数之间的调用关系经常漏掉。审查代码时，不能只看"函数有没有"，还要看"有没有被调用"。

❌ 问题 3：表格数据回填错列 — 点击行后表单数据全乱了

现象

点击表格某一行，"学号"显示成了"姓名"，"成绩"显示成了"测试日期"。

原因

桌面版表格列顺序：学号 | 姓名 | 项目 | 成绩 | 测试日期。
网页版在前面加了一列"序号"，列索引全部偏移了 1。原来的 JS 写的是 item(row, 0) 取学号，实际上 0 变成了序号列。

列索引桌面版网页版（多了序号列）
0学号序号 ❌
1姓名学号
2项目姓名
3成绩项目
4测试日期成绩
解决方案

把所有回填逻辑里的列索引统一 +1：

function fillPhysicalForm(row) {
    document.getElementById('physical-sid').value = table.item(row, 1).text();    // 原来是 0
    document.getElementById('physical-name').value = table.item(row, 2).text();   // 原来是 1
    document.getElementById('physical-item').value = table.item(row, 3).text();   // 原来是 2
    document.getElementById('physical-score').value = table.item(row, 4).text();  // 原来是 3
    document.getElementById('physical-date').value = table.item(row, 5).text();   // 原来是 4
}
经验

这种"索引偏移"Bug AI 自己不会发现，因为它生成代码时是按新表写的。只有人去和旧版对比时才能发现。

❌ 问题 4：批量导入 Excel 表头不匹配 — "缺少必要字段"

报错 
ValueError: Excel 表头不正确，缺少必要字段
原因

代码里硬编码了表头 ["学号", "姓名", "项目", "成绩", "测试日期"]，但用户拿来的 Excel 表头是 "学生学号", "名字", "测试项目", "分数", "日期"，列名对不上。

解决方案

放宽表头校验，允许别名映射：

def import_physical_excel(path: str) -> tuple:
    df = pd.read_excel(path)
    df.columns = df.columns.str.strip()

    col_map = {
        "学号": ["学号", "学生学号", "SID"],
        "姓名": ["姓名", "名字"],
        "项目": ["项目", "测试项目"],
        "成绩": ["成绩", "分数"],
        "测试日期": ["测试日期", "日期"]
    }

    # 找到实际使用的列名
    used = {}
    for std, aliases in col_map.items():
        for col in df.columns:
            if col in aliases:
                used[std] = col
                break
        else:
            raise ValueError(f"缺少必要字段：{std}")

    insert_sql = "INSERT INTO PHYSICAL_SCORE (STUDENT_ID, NAME, ITEM, SCORE, TEST_DATE) VALUES (?,?,?,?,?)"

    return inserted, updated, failed
经验

用户拿来的 Excel 永远不会和你预期的表头一模一样。做别名映射是标配，硬编码表头 = 自找麻烦。

❌ 问题 5：搜索框中文模糊匹配失败 — 明明有记录却搜不到

现象

搜索框输入"张三"，数据库里有这条记录，但表格显示"无结果"。

原因

JS 的 filter_table() 用的是 item.text().includes(text)，但某些单元格可能是 null（空单元格），调用 text() 会报错，整个过滤函数直接中断。

解决方案

加空值判断：

function filterPhysicalTable(text) {
    text = text.toLowerCase();
    for (let row = 0; row < table.rowCount; row++) {
        let match = false;
        for (let col = 0; col < table.columnCount; col++) {
            const item = table.item(row, col);
            if (item && item.text().toLowerCase().includes(text)) {
                match = true;
                break;
            }
        }
        table.setRowHidden(row, !match);
    }
}
经验

JS 里访问对象属性前，一定要先判空。AI 生成的代码经常漏掉这种边界情况。

❌ 问题 6：Chart.js 折线图偶尔不显示 — "Cannot read properties of null"

报错 
Uncaught TypeError: Cannot read properties of null (reading 'getContext')
原因

Chart.js 需要在页面加载完成后才能找到 <canvas> 元素。但网页用了 Tab 切换 + display: none 隐藏内容，canvas 在隐藏状态下 Chart.js 拿不到渲染上下文。

解决方案

改为在 Tab 被点击时才初始化图表：

// HTML：给 Tab 按钮加 data-target
<button class="tab-btn" data-target="#tab-chart">成绩分析</button>

// JS：点击 Tab 时才初始化图表
document.querySelectorAll('.tab-btn').forEach(btn => {
    btn.addEventListener('click', () => {
        if (btn.dataset.target === '#tab-chart') {
            initChart();  // 在这里初始化，而不是页面 onload
        }
    });
});

function initChart() {
    const ctx = document.getElementById('scoreChart').getContext('2d');
    new Chart(ctx, {
        type: 'line',
        data: { /* ... */ },
        options: { responsive: true }
    });
}
经验

DOM 元素在 display: none 状态下，很多 API 无法正常工作。需要等元素"可见"之后再操作。

❌ 问题 7：删除体能成绩无二次确认 — 一点就删了

现象

选中一行点"删除"，直接就删了，没有任何确认弹窗。

原因

桌面版 Qt 用的是 QMessageBox.question()，自带确认弹窗。网页版 AI 生成的代码直接调用了 fetch(..., {method: 'DELETE'})，没有任何确认逻辑。

解决方案

在删除前加 confirm() 弹窗：

function deletePhysical(row) {
    const sid = table.item(row, 1).text();
    const item = table.item(row, 3).text();

    if (!confirm(`确定删除学号 ${sid} 的「${item}」记录吗？`)) {
        return;  // 用户点"取消"，直接退出
    }

    fetch(`/api/physical/${sid}`, { method: 'DELETE' })
        .then(res => res.json())
        .then(json => {
            if (json.success) {
                loadPhysicalTable();
                alert('删除成功');
            }
        });
}
经验

删除操作一定要二次确认。AI 不会主动加这个，因为它不知道"误删"的严重性。

❌ 问题 8：Flask 启动报端口冲突 — "Address already in use: 5000"

报错 
OSError: [Errno 10048] Address already in use: 5000
原因

之前调试时 Flask 进程没有正常退出，或者电脑里其他程序（如之前跑过的 PySide6 版也用了 5000 端口）占用了端口。

解决方案（二选一）

方案一（推荐）：改端口号为 5001：

# run.py
if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5001, debug=True)

方案二：杀掉占用进程：

# Windows 命令行
netstat -ano | findstr 5000
taskkill /PID <进程号> /F
经验

调试时经常遇到端口被占，改端口号是最快的办法。正式部署时用 Nginx 反向代理，不暴露端口号。
