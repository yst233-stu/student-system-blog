桌面版 vs 网页版 —— 架构全面对比
PySide6 · Flask + HTML · 达梦数据库 · 2026年5月

📌 一、系统概述

本系统最初采用 PySide6 构建桌面客户端，后重构为 Flask + HTML 网页版。两个版本共用同一套达梦数据库（STUDENT / STUDY_SCORE / PHYSICAL_SCORE），数据完全互通，可无缝切换。

下面从 架构、体验、部署、性能、安全 五个维度，对两种形态进行深度对比。

⚖️ 二、核心差异总览

维度 桌面版（PySide6） 网页版（Flask + HTML）
架构模式 前后端一体，UI 与逻辑死死绑定 前后端分离，RESTful API 驱动
启动方式 运行 主程序.py，弹出 Qt 窗口 双击 启动系统.bat，浏览器自动打开
跨平台 需为不同 OS 编译不同版本 任何设备只要有浏览器就能访问
离线使用 ✅ 断网照样用 ❌ 依赖网络
部署分发 需 PyInstaller 打包，180MB+ 零安装，浏览器即开即用
界面美观 Qt 控件，偏"工程感" HTML/CSS，可高度定制
图表展示 matplotlib 嵌入，静态图 Chart.js 前端渲染，可交互
硬件集成 ✅ 可调用打印机、摄像头 ❌ 浏览器权限受限
安全性 本地存储，入口隐蔽 需防 SQL 注入 / XSS 等

🏗️ 三、架构对比：从"铁板一块"到"各司其职"

🔹 桌面版架构（All-in-One）

┌──────────────────────────────────────┐ │ PySide6 桌面窗口 │ │ ┌────────┐ ┌──────────────────┐ │ │ │ 按钮 │ │ QTableWidget │ │ │ │ 输入框 │ │ (显示数据) │ │ │ └────┬───┘ └────────┬─────────┘ │ │ │ │ │ │ ▼ ▼ │ │ ┌──────────────────────────────┐ │ │ │ 同一个 py 文件，全写在一起 │ │ │ │ UI + 数据库 + 逻辑 混装 │ │ │ └──────────────┬───────────────┘ │ │ ▼ │ │ ┌──────────────┐ │ │ │ 达梦数据库 │ │ │ └──────────────┘ │ └──────────────────────────────────────┘

👉 问题：UI、逻辑、数据操作全在一个文件里，功能一多就难以维护。

🔹 网页版架构（前后端分离）

┌──────────┐ HTTP/JSON ┌──────────────┐ SQL ┌──────────┐ │ 浏览器 │ ──────────→ │ Flask 后端 │ ──────→ │ 达梦 │ │ HTML/JS │ ←─────────── │ RESTful API │ ←────── │ 数据库 │ └──────────┘ 响应 JSON └──────────────┘ 结果 └──────────┘ ↑ 展示层 ↑ 逻辑层 ↑ 数据层 前端 后端 数据库

👉 优势：每一层只干一件事，改界面不影响数据库，改逻辑不影响页面。

🖥️ 四、用户体验：两种"手感"

🖱️ 桌面版体验

  • 启动即离线，不依赖网络
  • 操作流畅，本地资源直接调用
  • 菜单栏、快捷键符合桌面习惯
  • 可直接调用打印机、文件对话框
  • 界面风格偏"工具软件"

🌐 网页版体验

  • 无需安装，浏览器打开即用
  • 界面可做得更现代、更美观
  • Chart.js 图表可悬停查看数据
  • 支持响应式，手机也能看
  • 更新只需刷新，无需重新安装

🚀 五、部署与分发：谁更"省心"？

📦 桌面版分发流程

开发者 → PyInstaller 打包（含 Python 运行时）→ 生成 180MB+ exe → 用户下载 → 安装 → 运行

⚠️ 痛点：打包过程复杂，PowerShell 对中文路径支持差，依赖分析耗时，单文件体积大。

🌍 网页版分发流程

开发者 → 拷贝文件夹（app.py + templates + static）→ 用户双击 bat → 浏览器自动打开 或 → 部署到云服务器 → 用户访问网址即可

✅ 优势：零安装，用户零门槛，更新只需替换代码。

便携版文件清单：

  • run.py —— Flask 启动入口（含自动打开浏览器逻辑）
  • 启动系统.bat —— 双击启动 Flask 服务并打开浏览器
  • 安装依赖.bat —— 一键安装 flask / pandas / openpyxl / dmPython
  • 使用说明.md —— 分步骤说明首次使用和日常使用流程
  • templates/ —— HTML 页面
  • static/ —— CSS + JS + 图表

🔒 六、性能与安全

⚡ 性能对比

对于学生管理系统这类 轻量级 CRUD 应用，HTTP 请求带来的延迟（通常 <50ms）几乎感知不到。但在以下场景有差异：

场景桌面版网页版
启动速度快（本地直接加载）中（需启动 Flask 服务）
大数据量查询快（直接操作数据库）略慢（多了 HTTP 层）
图表渲染中（matplotlib 静态图）快（Chart.js 前端异步渲染）

🔐 安全性对比

安全维度桌面版网页版
数据泄露风险低（本地存储）中（暴露公网需防护）
SQL 注入几乎无需参数化查询防范
XSS 攻击不适用需输入校验 + 转义
认证授权无（本地使用）需 Session / Token 机制

⚠️ 注意：网页版若暴露公网，必须做好输入校验和权限控制。本系统目前为内网/本地使用，风险可控。

🎯 七、选型建议

你的场景推荐选择
答辩演示，求稳不求新桌面版（保底）
展示现代化架构能力网页版（加分）
需要离线使用桌面版
需要分发给多人网页版
需要连接硬件设备桌面版
需要快速迭代更新网页版
正式生产环境网页版 + 云服务器

✅ 八、总结

📝 一句话总结

桌面版胜在"稳" —— 离线可用、性能直接、安全隐蔽。
网页版胜在"活" —— 零安装、易部署、架构清晰、界面现代。

对于学生管理系统这类场景，网页版的综合优势更明显。
但保留桌面版作为保底方案，是答辩时最稳妥的策略 —— 双版本切换，数据互通，万无一失。
